# Direct3D 9 wrapper для Lineage II C4

**32-битный Windows-прокси** для клиентов на классическом `IDirect3D9`. В этом форке приоритет — корректное восстановление состояний игры и воспроизводимая сборка.

> **Не устанавливайте старую `d3d9.dll` из корня репозитория.** Это неизменённая upstream-сборка без новых исправлений. Используйте `out/c4/d3d9.dll` после сборки либо CI-артефакт соответствующей ревизии.

Проверенные `L2.exe` и `D3DDrv.dll` из `D:\Games\L2Siege\system` — x86, импортируют `Direct3DCreate9`. Регрессионные тесты на нативном D3D9 проходят на машине разработки. **Сама игра C4, защита сервера, Wine/DXVK и сторонние оверлеи ещё не протестированы.** Тестирование upstream на Kamael не гарантирует совместимость с C4.

## Сборка и тесты

Нужны Visual Studio 2022 с компонентами разработки C++, Windows SDK/x86 и CMake >=3.21. x64 и непроверенные компиляторы намеренно отклоняются.

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A Win32
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release --prefix out/c4
```

Результат: `out/c4/d3d9.dll` и `out/c4/d3d9_proxy.ini`. Эти команды **не меняют файлы игры**. MSVC runtime статический; экспортируются ровно восемь нужных функций; предупреждения компилятора считаются ошибками.

Тесты проверяют INI, Unicode/точки в путях, фокус и хоткеи, короткие интервалы ограничителя FPS, COM-ссылки, восстановление состояний, AF/LOD/fog, state blocks, Reset, освобождение depth, swap chains, настоящую отрисовку/Present и загрузку итоговой DLL. Если HAL недоступен, нативный тест отмечается как **пропущенный**, а не успешный. Игра в тестах не запускается. GitHub Actions собирает и публикует тот же Win32-пакет.

## Установка и откат

1. Закройте клиент. Убедитесь, что сервер разрешает графические врапперы. Не обходите защиту, если она отклоняет DLL.
2. Сохраните копии существующих `system\d3d9.dll` и `system\d3d9_proxy.ini`. Нельзя молча заменить DXVK/ReShade с тем же именем: цепочка локальных DLL здесь не реализована.
3. Скопируйте файлы из `out/c4` в `D:\Games\L2Siege\system`, рядом с `L2.exe`. Не затирайте пользовательский INI без необходимости.
4. Для первой проверки включите `[general] logging=1`. Лог: `system\d3d9_proxy.log`, дописывается при следующих запусках.
5. Запустите игру обычным способом, в том числе через существующий borderless-лаунчер. Проверьте вход, город/мир, интерфейс/чат, телепорт, Alt-Tab, Alt-Enter, сворачивание, фоновый FPS, переключение эффектов, разрешение и выход. Затем отключите логирование.
6. Для отката закройте игру и верните сохранённые DLL/INI. Если файлов прежде не было — удалите только установленный враппер и его настройки. Системный DirectX не трогайте.

`Option.ini`, зашифрованный `l2.ini`, настройки персонажа и скрипты запуска враппер не меняет.

## Настройки

Готовый профиль: [`config/c4/d3d9_proxy.ini`](config/c4/d3d9_proxy.ini). Если INI отсутствует, он создаётся рядом с загруженной DLL без перезаписи существующего файла. После редактирования нужен перезапуск. Некорректные числа заменяются значениями по умолчанию; диапазоны ограничены.

| Настройка | По умолчанию | Значение |
|---|---:|---|
| `general.logging` | 0 | Диагностика конфигурации, возможностей, переключений |
| `fps.limit` | 60 | Лимит активного окна, 0 выключает, максимум 1000 |
| `fps.min_fps` | 8 | Фоновый/свёрнутый клиент, 0 выключает, максимум 120 |
| `graphics.anisotropy` | 16 | 0/1 оставляет игровой AF; 2–16 ограничивается возможностями устройства |
| `graphics.lod_bias` | 0.0 | 0 сохраняет игровой LOD; override в диапазоне -4..4 |
| `fog.mode` | 0 | 0 игровой туман; 1 заданный цвет/дистанции; 2 игровой цвет/заданные дистанции |
| `latency.frame_latency` | 0 | Только опциональный API Device9Ex, диапазон 0–16 |
| `detector.enabled` | 0 | Счётчики draw/light и дамп запрошенного тумана; нужно logging=1 |
| `hotkeys.toggle` | ScrollLock | Только активное окно; пустое значение выключает |
| `hotkeys.detect` | пусто | Дамп детектора |

### AF, LOD и выключение эффектов

AF меняет только линейную/анизотропную минификацию. **Point-фильтрация и игровой mip-фильтр сохраняются.** Ненулевой LOD применяется только к фильтруемым mipmapped-семплерам при поддержке устройством. Отрицательный bias может усиливать мерцание — начальный профиль использует ноль.

Запрошенные игрой состояния хранятся отдельно от фактических override. OFF возвращает именно игровые значения. Getter-методы сообщают игровые значения. State blocks записывают/восстанавливают игровые состояния, а эффекты применяются перед следующим draw, не запекаясь в сохранённые блоки. Точные маски ALL/PIXEL/VERTEX обрабатывает D3D runtime. Неиспользуемых depth-текстур больше нет.

### Туман

Оба режима **уважают FOGENABLE игры**: проходы интерфейса/неба с отключённым туманом остаются без тумана. Это осознанное изменение относительно принудительного включения в upstream. Режим 1 задаёт цвет и линейные дистанции, режим 2 сохраняет игровой цвет. Настройки применяются до отрисовки, не в Present после неё. При отсутствии table fog используется vertex fog, если поддерживается; иначе остаются игровые состояния. Для первого запуска оставьте `mode=0`.

### FPS, задержка и хоткеи

Ограничитель использует QPC и waitable timer отдельно для устройства, включая остаток меньше миллисекунды. Нет busy-spin и изменения глобального разрешения таймера. **Точность 0,1 мс не гарантируется:** влияет планировщик Windows. При смене лимита сбрасывается временная база. Swap-chain Present тоже обрабатывается; явный DONOTWAIT не задерживается. OFF отключает лимиты вместе с эффектами.

FPS cap **не управляет глубиной очереди GPU**. `SetMaximumFrameLatency` вызывается только по запросу, если устройство предоставляет Device9Ex и исходное значение можно прочитать/восстановить. На проверенном классическом Windows-пути получен `E_NOINTERFACE`. При logging=1 видна доступность функции. Скрытого GPU-sync fallback и обещания снижения input lag нет. Классические устройства не переводятся в Ex — важна совместимость managed-ресурсов.

Хоткеи работают только в активном viewport и игнорируют клавишу, уже удерживаемую при получении фокуса. Заголовок окна не меняется. Доступны RightAlt, RightCtrl, Home, End, PageUp, PageDown, Insert, Delete, ScrollLock, Pause и hex VK, например `0x77`.

## Границы поддержки

- Инициализация вне DllMain, Unicode-пути относительно DLL, загрузка оригинального DirectX по системному пути. Одна ссылка на модуль runtime намеренно остаётся до завершения процесса: оригинальные ресурсы могут пережить прокси.
- Базовые COM-интерфейсы сохраняют identity и собственные счётчики ссылок. GetDirect3D и GetDevice у state blocks/swap chains возвращают прокси. Неизвестные/Ex-интерфейсы возвращают E_NOINTERFACE, не «голое» устройство.
- Флаг `D3DCREATE_PUREDEVICE` снимается: для сохранения состояний нужны getter-методы runtime.
- D3DPERF передаётся системному runtime. Нет сетевых операций, внедрения в другой процесс или патчей памяти игры.
- **Это не универсальная обёртка всего D3D9:** текстуры, поверхности, буферы, шейдеры и запросы остаются оригинальными объектами. Их GetDevice может вернуть оригинальное устройство; рендеринг через него обходит эффекты. Полная обёртка ресурсов и цепочки сторонних DLL не реализованы. Одновременное изменение одного устройства из нескольких потоков не поддерживается; целевой сценарий — старый однопоточный рендер C4.
- AF улучшает фильтрацию, а не CPU-bound производительность на осадах. Сравнивайте одинаковые сцены и frametime.
